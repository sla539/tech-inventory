# Облік техніки: інструкція запуску

Новий окремий сайт для обліку принтерів і ноутбуків. Працює на Firebase (вхід + база даних + хостинг), Google-таблиця не потрібна. Старий сайт не чіпаємо.

## Що всередині

| Файл | Призначення |
|---|---|
| `index.html` | Каркас сторінки |
| `style.css` | Вигляд («Корпоративний»: бокове меню, світла й темна тема) |
| `config.js` | **Ваші налаштування Firebase** (заповнюєте самі) |
| `app.js` | Уся логіка сайту |
| `firestore.rules` | Правила безпеки бази (**теж потрібно заповнити UID**) |
| `firebase.json` | Налаштування публікації |

## Крок 1. Створіть проєкт Firebase

1. Відкрийте https://console.firebase.google.com і увійдіть через Google-акаунт.
2. Натисніть **Create a project** (Створити проєкт), введіть назву, наприклад `tech-inventory`.
3. Google Analytics можна вимкнути. Натисніть **Create project**.

## Крок 2. Увімкніть вхід за email і паролем

1. Зліва: **Build → Authentication → Get started**.
2. Вкладка **Sign-in method** → **Email/Password** → увімкніть → **Save**.

## Крок 3. Створіть базу даних

1. Зліва: **Build → Firestore Database → Create database**.
2. Режим: **Production mode**.
3. Регіон оберіть найближчий (наприклад `europe-central2` Warsaw або `eur3`). Потім його не змінити.

## Крок 4. Отримайте налаштування для сайту

1. Шестерня біля **Project Overview → Project settings**.
2. Внизу блок **Your apps** → іконка **`</>`** (Web) → назва, наприклад `web` → **Register app**.
3. Скопіюйте об'єкт `firebaseConfig` і перенесіть значення у файл **`config.js`** (поля `apiKey`, `authDomain`, `projectId` та інші).

## Крок 5. Створіть головного адміністратора

1. **Authentication → Users → Add user**: введіть свій email і пароль.
2. У таблиці скопіюйте значення **User UID** біля нього.
3. Вставте цей UID у **двох** місцях:
   - `config.js` → `ADMIN_UID`
   - `firestore.rules` → `mainUid()` (замість `ВСТАВТЕ_UID_ГОЛОВНОГО_АДМІНА`)

## Крок 6. Опублікуйте правила безпеки

1. **Firestore Database → Rules**.
2. Видаліть усе, вставте вміст файлу `firestore.rules` (з уже вписаним UID) → **Publish**.

## Крок 7. Перевірте на своєму комп'ютері

У папці з файлами відкрийте термінал і запустіть один із варіантів:

```
python -m http.server 8080
```
або (якщо встановлено Node.js) `npx serve .`

Відкрийте http://localhost:8080 і увійдіть email/паролем із кроку 5. Додайте тестовий принтер: **Принтери → ＋ Принтер**.

> Просто відкрити `index.html` подвійним кліком не вийде: браузер забороняє модулі з файлів. Потрібен локальний сервер.

## Крок 8. Опублікуйте сайт в інтернеті (Firebase Hosting)

1. Встановіть Node.js (https://nodejs.org), потім у терміналі:
   ```
   npm install -g firebase-tools
   firebase login
   ```
2. У папці з файлами:
   ```
   firebase use --add
   ```
   Оберіть свій проєкт і дайте йому псевдонім `default`.
3. Публікація (сайт + правила):
   ```
   firebase deploy
   ```
4. У кінці вийде адреса виду `https://ВАШ-ПРОЄКТ.web.app`. Це і є ваш сайт.

Оновлення сайту згодом: змініть файли й знову `firebase deploy`.

## Крок 9. Додайте колег

1. Колеги відкривають сайт → **Реєстрація**.
2. Ви заходите в **Користувачі** й призначаєте роль:
   - **перегляд**: лише дивиться;
   - **технік**: додає/редагує пристрої, видає, приймає, пише роботи, звіряє, друкує етикетки;
   - **адмін**: усе, а також видалення й керування користувачами.

## Як користуватись

- **Пристрій → картка** (відкривається по кліку): вкладки «Інформація / Історія / Роботи / Файли».
- **Видати / Прийняти**: видача людині або в кабінет, повернення на склад. Видати можна лише пристрій зі статусом «на складі».
- **Звірити**: фіксує дату в історії. Пристрої без звірки довше за `INV_DAYS` днів (у `config.js`) рахуються «не звіреними».
- **Етикетки**: вибрати пристрої → друк. QR на наклейці відкриває картку пристрою.
- **Звіти**: роботи й витрати за період, підсумки по пристроях і відповідальних, кнопка друку.

## Обмеження цієї першої версії

- Файли й фото зберігаються прямо в базі (до ~0,9 МБ кожен), бо Firebase Storage потребує платного тарифу. Фото стискаються автоматично.
- Склад матеріалів, заявки від користувачів і перенесення даних зі старої таблиці в цей приклад **не входять**. Їх можна додати наступними кроками.
- Усі події завантажуються в браузер цілком, що добре для сотень пристроїв. Для тисяч знадобиться пагінація запитів.
